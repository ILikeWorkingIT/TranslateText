# UC-005: Задать кастомную инструкцию

**Статус артефакта:** `Черновик, требует согласования`  
**Уровень:** user goal  
**Связанные US:** US-005  
**Связанные ФТ:** FT-007, FT-008, FT-011, FT-029; NFT-014  
**Связанные сценарии:** инструкция уходит в каждый фрагмент UC-001  
**Источники:** ТЗ; глоссарий; US-005; A0003; A0006; A0014; A0050; A0052; A0060; A0065; A0069; A0072

## 1. Акторы

| Роль | Тип | Участие |
| --- | --- | --- |
| Пользователь | Primary | Видит и меняет «Кастомную инструкцию», подтверждает или отменяет перевод при пустом поле |
| Ollama | Supporting | Получает снимок кастомной инструкции со старта очереди в каждом запросе фрагмента |

## 2. Предусловие

- TranslateText открыто.

## 3. Триггер

Пользователь открывает TranslateText (показ значения по умолчанию) либо изменяет поле «Кастомная инструкция».

## 4. Основной поток

1. Пользователь открывает TranslateText.
2. Система показывает в поле «Кастомная инструкция» базовый промпт переводчика, пока Пользователь не заменил это значение (FT-008, A0006).
3. Пользователь при необходимости заменяет текст поля своим (стиль перевода, A0003).
4. Пользователь запускает перевод (UC-001) при непустой инструкции.
5. Система передаёт в каждый фрагмент очереди снимок кастомной инструкции и модели со старта этой очереди (FT-011, A0052).
6. Пользователь получает перевод, выполненный с этой инструкцией (результат в UC-001).

## 5. Альтернативные потоки

### 5.1. Некорректные данные

**[Шаг 4.1]** Пользователь очистил «Кастомную инструкцию», в «Оригинальный текст» есть текст, выполняется «Перевести»: система сообщает, что инструкция отсутствует и будет добавлен базовый промпт переводчика, и спрашивает согласие на перевод или отмену (FT-029, A0014). При согласии система подставляет базовый промпт в поле «Кастомная инструкция» и выполняет перевод с этим промптом (A0050). → возврат к шагу 2 UC-001 (снимок, блокировка, NFT-002). При отмене поле остаётся пустым — см. 5.3.

### 5.2. Timeout / недоступность

Не применимо к редактированию поля. Таймаут и недоступность Ollama обрабатываются в UC-001 / UC-007, не в смене инструкции.

### 5.3. Прерывание

**[Шаг 4.2]** На запросе согласия из 5.1 Пользователь отменяет перевод: система не начинает перевод, не вызывает Ollama и не подставляет базовый промпт в поле (FT-029, A0050). → завершение.

### 5.4. Недостаточно прав

Не применимо (A0002).

### 5.5. Конкурентный доступ

**[Шаг 4.1]** Пока идёт очередь, Пользователь меняет «Кастомную инструкцию»: смена поля на эту очередь не влияет (FT-011, A0052, A0060). Новую очередь Пользователь не стартует: «Перевести» заблокирована (FT-031). Несколько Пользователей не предусмотрены (A0002). → текущий поток UC-001 продолжается.

### 5.6. Граничные значения

**[Шаг 2.1]** Пользователь не менял поле: остаётся базовый промпт переводчика (A0006). → возврат к шагу 4.

**[Шаг 3.1]** Пользователь заменил инструкцию своим текстом **до** старта очереди: в каждый фрагмент уходит снимок этой инструкции (FT-011, NFT-014, A0052). Смена поля во время уже идущей очереди на этот запуск не влияет. → возврат к шагу 4.

## 6. Потоки исключений

**E1 — Согласие при пустом поле, затем сбой Ollama.** Перевод с базовым промптом начат по FT-029; дальнейший сбой — UC-001 E1/E2, UC-007. → завершение по тем UC.

**E2 — Пустая инструкция и пустой оригинал.** «Перевести» заблокировано (FT-026); запрос согласия FT-029 не запускается без «Перевести». → завершение (сценарий смены инструкции может остаться на шаге 3).

## 7. Постусловие

**Успех:** в запросах перевода фрагментов передан снимок кастомной инструкции со старта очереди (FT-011, A0052, A0065); при согласии после пустого поля в «Кастомная инструкция» виден базовый промпт переводчика (A0050).  
**Отказ:** Пользователь отменил перевод при пустой инструкции; Ollama не вызывалась; поле остаётся пустым.
