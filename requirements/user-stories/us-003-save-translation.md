# US-003: Сохранить перевод вручную

## User Story

Как Пользователь,
я хочу сохранить содержимое «Русский перевод» в файл `.txt` или `.docx` туда, куда я выберу,
чтобы забрать результат независимо от автосохранения.

**Статус:** `Черновик, требует согласования`  
**Приоритет (MoSCoW):** Must  
**Источник:** ТЗ; глоссарий; A0022; A0040; A0047; A0048; A0054  
**Связанные ФТ:** FT-002, FT-004, FT-027, FT-040, FT-043, FT-044, FT-046

## Acceptance Criteria (Gherkin)

### AC1 — Экспорт при непустом переводе

Given в «Русский перевод» есть текст
When Пользователь выполняет «Сохранить перевод» и выбирает `.txt` или `.docx`
Then система записывает содержимое правого поля в выбранный файл (FT-004)

### AC2 — Не зависит от автосохранения

Given галочка «Автосохранение» включена или выключена
When Пользователь выполняет «Сохранить перевод»
Then действие выполняется независимо от галочки (A0022)
And диалог показывает только `.txt` и `.docx`, иные форматы не предлагает и не записывает (FT-046, A0054)

### AC3 — Пустой перевод

Given поле «Русский перевод» пусто
Then кнопка «Сохранить перевод» заблокирована (FT-027, A0040)
And галочка «Автосохранение» не блокируется по этой причине

### AC4 — Edge case: файл уже есть, автосохранение или ручная запись не удались

Given по выбранному пути уже есть файл
When Пользователь выполняет «Сохранить перевод»
Then система следует диалогу ОС «заменить / отмена»; при отмене существующий файл не меняется (FT-043, A0047)

Given автосохранение не записало файл в `output`
And в «Русский перевод» есть текст
When Пользователь выполняет «Сохранить перевод»
Then система не блокирует кнопку из‑за сбоя `output` (FT-040, A0030)
And Пользователь может сохранить перевод выбранным путём

Given запись выбранного Пользователем файла не удалась
Then система оставляет текст в «Русский перевод», показывает, что запись не удалась, и не блокирует кнопку (FT-044, A0048)
