# Чеклист срезов MVP TranslateText

Дата: 2026-08-26  
Назначение: порядок **маленьких рабочих кусков** «от кнопки до результата». Не план «сделай всё приложение».

Канон: ФТ (`A0086`), НФТ (`A0087`), US/UC (`A0088`, `A0089`), словарь данных (`A0091`). Пустое поле — длина 0 символов Unicode; «только пробелы = пусто» в источниках нет. Макет окна уже есть (`src/ui/`) — это **не** рабочий MVP.

## Как пользоваться

Один запрос агенту — **один срез** (`S-01` … `S-14` ниже). В запросе явно: «только этот срез, следующий не начинать».

Нельзя (раздует объём): «сделай рабочим», «реализуй все ФТ», «сделай перевод», «очередь + 100k + PDF + таймаут + диалоги».

Можно: «Срез S-04 из `reports/checklist.md`. Не начинай S-05.»

После среза:

1. Проверить критерий «срез готов» руками (launcher в проводнике).
2. Отметить `[x]` в этом файле.
3. Отдельной командой — `/new-tests`, затем `/use-tests`. В том же ходе, что код среза, тесты не писать и не гонять.

Слой: UI-хром — `/frontend`; Ollama, нарезка, файлы, очередь — `/app-layer`. Если срез трогает оба слоя — допустимы **два** запроса подряд (сначала `/app-layer`, затем клей `/frontend`), всё ещё только этот срез. Не начинать следующий.

Критерий раннего среза — приёмка **на тот момент**, не финальный канон. Пример: после S-01 кнопка «Перевести» доступна при непустом оригинале; после S-03 действует ещё FT-048. Перепроверять S-01 как «кнопка всегда живая, если есть текст» после S-03 нельзя.

Пока поздний срез не сделан, в продукте есть **временный пробел** (например между S-04 и S-06 огромный текст ещё может уйти в Ollama). Приёмку раннего среза вести только на его полоске, не на запрещённых для него объёмах.

## Запрет смешивать в одном срезе

| Не класть вместе | Почему |
| --- | --- |
| Очередь + автосохранение + открытие файла | Это три разных «от кнопки до результата» |
| Перевод + лимит 100k + диалог пустой инструкции | Агент тянет все ветки `StartTranslation` сразу |
| Все форматы файла в первом «Открыть» | Сначала `.txt`/`.md`, потом `.docx`/`.pdf` |
| Сбой фрагмента вместе с первым успешным переводом | Сначала happy path одного фрагмента |
| Очередь по абзацам + резка сверхдлинного абзаца (FT-025) | FT-025 — отдельный срез S-07b |
| Автоопрос моделей при фокусе окна приложения | Вне MVP (`A0079`) |

| Не входит | Сообщение про `start_ollama.bat`, блокировка «Перевести» без Ollama, сам перевод, автоопрос при фокусе **окна** (`A0079`). |
| Слои | `/app-layer` (`OllamaGateway`, `refresh_models`), затем `/frontend` |
| US / UC | US-004 / UC-004 |
| Приёмка НФТ | NFT-003: 10 успешных опросов подряд при живом Ollama — замер, не отдельный код. |

**Срез готов**, когда:

- При запущенном Ollama список «Модель» совпадает с ответом локального API, без отсечения по имени.

- Повторный клик или фокус на «Модель» обновляет список; прежний выбор сохраняется, пока имя есть в новом ответе; если имени нет и список не пуст — снова FT-041.
- Новая модель, появившаяся в Ollama, видна после одного такого опроса, без пересборки приложения.
- Возврат фокуса в окно приложения **без** клика/фокуса на «Модель» сам API не опрашивает.

**Срез готов**, когда:

- Новый запуск при включённом автосохранении: уже сохранённый полный перевод в `output` не дублируется; неполный после сбоя фрагмента попадает в `output` до замены поля.
