## Пайплайн, который сработал

Маленькая LLM **не** должна собирать SD-промпт и выбирать LoRA.

1. Русский текст пользователя.
2. Скрипт по словам запроса подбирает 0–1 LoRA (пересечение с `GET /sdapi/v1/loras`).
3. Ollama **только переводит** фразу на английский (1–2 предложения, JSON `prompt` + `negative_prompt`).
4. Скрипт чинит цвет из русского (`синем` → blue, чужой black выкинуть).
5. Скрипт дописывает ключевые слова (`score_9, 1girl, …`) и `<lora:name:0.8>`.
6. `POST http://127.0.0.1:7860/sdapi/v1/txt2img`. Forge часто отдаёт JPEG, не PNG — смотреть magic bytes.

Порядок в итоговом промпте: **перевод → score/1girl → цвет → LoRA → цвет ещё раз** (LoRA латекса перекрашивает в чёрный, цвет после тега это ломает).

## Почему не отдавать LoRA в qwen2.5:3b

Модель 3B с списком ~150 имён:

- вставляет `Pony_…` как **лошадь**, хотя `Pony_` = архитектура чекпоинта;
- цепляет случайные персонажи (`gwen_prison_suit4`) к сцене про латекс;
- пишет теги без сцены и путает цвета (синий → black).

Правило: 3B = переводчик. Отбор LoRA и цвет = детерминированный код.

## Отбор LoRA (логика)

- Только `.safetensors`, пересечение с Forge.
- Выкинуть обучение `-\d{6}$` и чужие линейки: папки/имена FLUX, WAN, LCM, SD15.
- В имени игнорировать стоп-слова: `pony`, `illu`, `sdxl`, `suit`, `v1`… — иначе «комбинезон» матчит `prison_suit`.
- Русский → английские ключи (`латекс`→`latex`, `гвен`→`gwen`). Совпадение только по отличительным токенам (длина ≥ 5 или явное имя вроде gwen).
- Максимум **одна** LoRA за запрос. Две латексных сразу (Doll + Maid) мешают друг другу.
- Если нет уверенного матча — без LoRA лучше, чем случайная.

Сверка с Forge: `GET /sdapi/v1/loras`. Генерация: `POST /sdapi/v1/txt2img` (timeout ≥ 300 с).

## Цвет

Не доверять переводу 3B. Скрипт:

- читает русские основы (`синем`/`синий` → blue; не путать `син` с «апельсин»);
- вычищает из английского чужие цвета;
- если в переводе нет нужного цвета, вставляет его (`black latex` → `blue latex`);
- в negative кладёт соперников (`black`, `white`, …).

## Чекпоинт Pony vs животное «пони»

Если пользователь написал девушку, а не лошадь:

- в negative: `horse, pony, foal, equine`;
- из текста перевода вычищать слова pony/horse;
- в промпт не класть голое имя файла LoRA (`pony_gwen_…`) — Forge воспринимает это как субъект.

Теги качества Pony: `score_9, score_8_up, 1girl` — дописывает скрипт, не LLM.

## UX

Длинное описание: многострочный ввод, конец `END`/`end` (не аргумент cmd). После перевода и перед Forge **печатать статус**: иначе 1–3 минуты выглядят как зависание. `print(..., flush=True)`.

Рядом с картинкой всегда `.txt` (русский запрос + итоговый промпт) — без этого нельзя отладить LoRA/цвет.

## API Ollama

`POST http://127.0.0.1:11434/api/chat`, `format: json`, `stream: false`.

Для 3B на CPU: `num_predict` ограниченный (~280), `repeat_penalty` ~1.3, таймаут до 600 с. Модель любит зациклить `negative_prompt` — парсить даже обрезанный JSON (достать `"prompt": "..."`). Первый ответ после старта контейнера медленный.

Системный промпт: «ты переводчик, не prompt engineer».
