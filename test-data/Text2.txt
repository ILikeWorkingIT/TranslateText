Дело в том, что я хочу иметь MAS как отдельную настройку в Cursor, чтобы я мог работать с и MAS и без него при необходимости в том же проекте.
1. Архитектура 
Cursor предлагает три механизма, у каждого своя зона ответственности —лучше использовать все три:
* Cursor Custom Agents (Modes) — изолированные системные промпты для ролей. Реальная «мультиагентность».
* `.cursor/rules/*.mdc` — всегда-включенные охранные правила и руководящие принципы по ролям.
* `.cursor/commands/*.md` (slash-команды) — параметризованные точки входа в этапы и сценарии.
* `.cursor/skills/*/SKILL.md` — исполнительный слой; PM указывает, какой скилл какую роль исполняет.
Принципы:
* - **PM — единая точка входа.** Всегда говорим с PM. Он определяет: этап, входной манифест, целевую роль, чек-лист ревью.
* - **Передача через артефакты.** Каждый этап: `INPUT MANIFEST ? OUTPUT ARTIFACT ? REVIEW MANIFEST ? GATE`. Агенты читают **только манифест входа**, не всю документацию.
* - **Блокирующий гейт.** После исполнителя PM **обязательно** запускает anatomist. Замечания уровня `critical`/`major` блокируют переход; `minor` — рекомендации. Подтверждение этапа — **вы** в `reports/pm-state.md`.
* - **Состояние — Markdown.** `reports/project-config.md` (конфигурация при инициализации), `reports/pm-state.md` (текущий этап, статус ревью, очередь действий), `reports/traceability.md` (матрица US/UC/FR/NFR/ADR/тесты).
2. Дополнительные файлы в структуру
Агенты работают в отдельных чатах только со своими файлами. Они не читают файлы проекта, которые им не требуются для выполнения поставленной им задачи.

Имеющееся (см. `.cursor/skills/`) — раскладываем; недостающее — создаём.
4.1. PM
PM-агент (оркестратор + delivery management)
o - **Оркестрация:** маршрутизация этапов, выбор исполнителя, запуск anatomist, блокирующий гейт. Playbook в `agent-pm.mdc`.
o - **Анализ коммитов vs требования:** сравнивает `git log` за окно с реестрами FR/US/UC, ищет orphan-коммиты и drift; по умолчанию автоматический обход репозитория. Скилл NEW `skill-commit-vs-requirements`. Артефакт: `reports/commit-audit/YYYY-MM-DD.md`. Обновляет колонку `commit refs` в `reports/traceability.md`.
- **Дейли-контекст:** утренняя сводка «вчера сделано / открытые задачи / встречи / блокеры» из git + meetings. Скилл NEW `skill-daily-context-briefing`. Артефакт: `reports/daily/YYYY-MM-DD.md`.
- **Отчётность для заказчика:** weekly digest и презентация — **формат** у TechWriter, **сбор фактов** у PM (commit-audit + meeting actions + daily briefs).

PM выполняет две функции: оркестратор документации и delivery-менеджер (бэклог, оценка, коммит-аудит, дейли-контекст, action items со встреч). Pm отвечает за управление проектом, руководит другими агентами и общается с заказчиком. Существует пять режимов:
1. Режим проекта. Подробная информация ниже. 
2. Режим фичи в неопубликованном проекте.  (есть только код с репозиторием). Нужно сначала восстановить требования по коду и только потом делать фичу. Сокращенный режим проекта. 5. Подготовка отчетности о проделанной работе / функционалу системы.
