# Описание проекта:

Пет-проект **TranslateText** разработан, чтобы системно прокачать AI-assisted разработку в **Cursor** (в том числе практику vibe coding) и освоить работу с **локальными моделями** через **Ollama**, без облачных API и без отправки текста во внешние сервисы.

**Стек:** Python 3, окно на customtkinter, httpx (клиент к локальному API Ollama), python-docx и pypdf, pytest, сборка Windows-приложения (`TranslateText.exe`). Своего HTTP-сервера, FastAPI/Flask и облачных ключей в продукте нет: перевод идёт на `localhost`.

В качестве учебной и продуктовой задачи выбран **машинный перевод больших текстов и документов** между английским и русским (**EN→RU** и **RU→EN**). Это удобный полигон: длинный ввод, работа с файлами, очередь фрагментов, прогресс, отмена, обработка ошибок, когда локальная модель недоступна.

## Этапы выполнения проекта:

Работа шла не «сразу в код», а этапами: границы продукта, требования, диаграммы сценариев, доменная модель, затем маленькие рабочие срезы интерфейса и прикладного слоя, проверка качества и релиз. Срезы и агенты в Cursor — способ вести этот цикл, а не замена ему.

1. **Границы продукта.** Зафиксировали, зачем нужен локальный перевод, что входит в MVP и что сознательно снаружи. Предварительное ТЗ: [documentation/Specification.md](documentation/Specification.md). Vision & Scope: [artifacts/vision-scope.md](artifacts/vision-scope.md). Техническое задание по ГОСТ 34.602-89: [artifacts/tz-gost-34-602.md](artifacts/tz-gost-34-602.md).
2. **Требования.** Собрали общий язык и проверяемое поведение: [глоссарий](requirements/glossary.md), [функциональные требования](requirements/functional-requirements.md) (FT-001…FT-055), [нефункциональные требования](requirements/non-functional-requirements.md) с метриками (NFT-001…NFT-014), десять [user stories](requirements/user-stories/) (US-001…US-010) и десять [use cases](requirements/use-cases/) в формате Cockburn (UC-001…UC-010). Закрытые решения по ходу уточнений: [requirements/answers-project.md](requirements/answers-project.md).
3. **Диаграммы сценариев.** По use cases нарисовали две sequence-диаграммы Mermaid (GitHub показывает их прямо в файле): [предупреждение о несохранённом переводе](diagrams/diagram-mermaid-001.md) (UC-006) и [опрос моделей при старте и восстановление Ollama](diagrams/diagram-mermaid-002.md) (UC-004, UC-007).
4. **Доменная модель.** Описали сеанс перевода как ограниченный контекст: агрегат, инварианты очереди, направление EN↔RU, нарезка фрагментов. [Модель DDD](requirements/domain-model.md), [словарь данных](requirements/data-dictionary.md). Стек и связи требований с кодом: [reports/project-config.md](reports/project-config.md), [reports/traceability.md](reports/traceability.md).
5. **Среда в Cursor.** Чтобы не вести проект одним бесконечным чатом, в репозитории собрана мультиагентная обвязка: роли (PM, аналитик, архитектор, технический писатель, дизайнер, разработчики UI и прикладного слоя, тестировщик), скиллы и slash-команды. Описание: [documentation/mas-description.md](documentation/mas-description.md). Список команд: [.cursor/list-commands.md](.cursor/list-commands.md).
6. **Реализация срезами.** Сначала макет окна (вид и клики без логики), затем рабочие куски S-01…S-13: блокировки кнопки, список моделей, перевод фрагмента, очередь, отмена, файлы, приёмка времени. Чеклист: [reports/checklist.md](reports/checklist.md). UI — `src/ui/` (customtkinter); прикладной слой — `src/domain/`, `src/services/`, `src/use_cases/`; сборка exe — `src/build-exe.bat`.
7. **Проверка качества.** Согласованность пакетов: [ФТ/НФТ](reports/incompatibility-ft-nft.md), [US/UC](reports/incompatibility-us-uc.md), [доменная модель](reports/domain-model-review.md). Автотесты pytest по поверхности desktop/customtkinter (в приёмке MVP — 200 passed): [tests/](tests/), отчёт [reports/test-run.md](reports/test-run.md). Замер NFT-001: [reports/nft-001-measurement.md](reports/nft-001-measurement.md).
8. **Релиз MVP 1.0.** Сборка Windows-приложения, [примечания к релизу](reports/release/release-v1.0.md) и [инструкция установки](reports/instruction.md) на другом компьютере без Docker.
