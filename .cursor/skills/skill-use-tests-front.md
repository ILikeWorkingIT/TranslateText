# Прогон автотестов

Универсальный скилл. Не подставляй факты другого проекта. Не привязывай текст к домену репозитория.

Роль: тестировщик. Гоняешь набор **сам**, пишешь отчёт для фикса, пользователю — короткое резюме. Не пишешь новые тесты (`skill-new-tests-front` не запускай).

---

## Редирект (сразу)

| Запрос | Действие |
| --- | --- |
| Только написать / добавить тесты, без прогона | Остановись. Нужна `/new-tests`. |
| Нет файлов тестов и нет команды в README/`package.json` | Не выдумывай набор. Предложи `/new-tests` (Python UI: pytest). Раннер не ставь молча. |

---

## Бюджет (антипетля)

На **один** запуск скилла, жёстко:

| Лимит | Значение | Если исчерпан |
| --- | --- | --- |
| Попыток фикса на один `BUG-…` (правка кода + перепроверка изолята) | **2** | Статус **`стоп-лимит`**, в чате: не закрыт. Дальше не правь этот ID в этом запуске |
| Прогонов **полного** набора (включая первый) | **4** | Больше полный набор не гоняй. Изолированный тест (шаг 1 в §6) и verbose-повтор §3 в лимит не входят |
| Повторов одной и той же команды после kill по таймауту | **0** | Не запускай ту же строку без таймаута. Тип `env` или `test_defect` (GUI / `sleep` / watch) |

**Нет прогресса:** повтор изолированного теста после правки дал тот же assert / ту же строку — это израсходованная попытка. После двух таких — `стоп-лимит`, не третья правка.

Счёт попытки: изоляция **до** первой правки — диагностика, не попытка. Попытка = изменил продукт (или импорт, без которого набор не стартует) + снова этот тест.

**Запрещено:** watch-режим (`vitest` без `run`, `jest --watch`, `npm test` в интерактиве). Только одноразовый прогон.

## SOP (порядок фиксирован)

### 0. Режим (один)

| Режим | Когда | Что делать |
| --- | --- | --- |
| **прогон** | `/use-tests`, «прогони», «какие баги» | §1–§5. Код не трогай |
| **прогон и исправление** | есть «исправь» / «почини» / «зафикси» | §1–§5, **затем** §6 в бюджете выше |
| **повтор** | «перепрогони». Отчёта ещё нет — как **прогон** | §1–§5, обнови статусы, если файл отчёта был. Фикс только если снова сказали «исправь» |

«Прогони» без «исправь» = **прогон**. Молча не лечи.

### 1. Команда запуска (кроссплатформа)

Агент запускает тесты **сам**. Пользователя не проси. Ручной чек-лист окна запрещён.

Ищи **одну** команду. Сначала поверхность по `src/` (как в `skill-new-tests-front`: web vs desktop/Python). Не бери `package.json` как главный раннер, если в `src/` нет JS/TS, а есть Python.

Порядок внутри выбранной поверхности — первое явное совпадение:

**Web / JS:**

1. Команда в README — она. Watch → флаги §1.1.
2. `package.json` `scripts.test` → менеджер по lockfile (`yarn.lock` → `yarn`, `pnpm-lock.yaml` → `pnpm`, иначе `npm`) и `<pm> test` с `CI=true` (PowerShell: `$env:CI='true'; npm test`).
3. Нет `scripts.test`: если в зависимостях **и** Vitest, **и** Playwright — не угадывай, возьми README или спроси одну команду. Иначе: только Vitest → `<pm> exec vitest run`; только Playwright → `<pm> exec playwright test` (headless, без `--ui` / `--headed`, пока не просили).

**Python / desktop:**

1. README, если там pytest/unittest, не запуск GUI.
2. `uv.lock` / `uv` → `uv run pytest`; `poetry.lock` → `poetry run pytest`; иначе `python -m pytest`.

Каталог по умолчанию — `tests/`. Не `test-data/`. Архив — только `@`.

**§1.1 Одноразовость:** не оставляй watch. Vitest: только `vitest run`. Jest: `CI=true` или `--watchAll=false`.

Команда, которая открывает окно приложения вместо раннера — не запускай.

Нет ни файлов тестов, ни команды раннера — стоп, предложи `/new-tests`. Есть команда, файлов нет — запусти; 0 collected не выдумывай как зелёный продукт, в чате: набор пуст, нужна `/new-tests`.

### 2. Первый прогон

1. Весь набор, пока пользователь не сузил путь.
2. Флаги краткости, если раннер позволяет: pytest `--tb=short`; иначе аналог «короткий failure».
3. Таймаут: unit без новой строки **120 с** — убей процесс. Весь прогон **10 мин** без конца — убей. Это не зелёный.
4. Счётчики: passed / failed / error / skipped / hung / не стартанул. **0 collected** — не PASS: в чате вердикт FAIL, «набор пуст», предложи `/new-tests`.

Сырой лог **не** копируй в чат. Нужен разбор — только `--tb=short` / эквивалент в файл отчёта.

### 3. Классификация (каждое падение — один тип)

| Тип | Когда | Фикс в этом скилле |
| --- | --- | --- |
| `product_bug` | эталон теста = ФТ/US/UC/`Axxxx`, код иначе | да, только режим исправления, бюджет |
| `test_defect` | ложный эталон, GUI, `sleep`, нет cleanup, мок внутренностей, watch/хрупкий селектор | нет. Предложи `/new-tests`, не запускай |
| `env` | нет зависимости, нет прав, нет модели/БД, нет дисплея | нет. Напиши, чего не хватает |
| `unknown` | лога мало | **Один** verbose-повтор **этого** теста (`-s` / verbose reporter). Не больше **трёх** таких повторов за запуск. `print()` в продукт не оставляй. Если всё ещё неясно — оставь `unknown`, не крути |

Несколько падений одной причины — отдельные `BUG-…`, в примечании «как BUG-001».

### 4. Файл `reports/test-run.md`

Перезапиши целиком (иной путь — только если задал пользователь). Без полного stdout.

Шапка: дата-время; **точная команда**; OS; каталог; итог цифрами; режим; сколько попыток фикса израсходовано.

Раздел «Кратко»: 2–4 предложения.

Раздел «Очередь исправления» (пустая, если всё зелёное):

| ID | Тест | Файл теста | Тип | Воспроизведение | Ожидание | Факт | Требования | Где чинить | Доказательство | Статус |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |

- ID: `BUG-001`… в этом прогоне, не переиспользуй номера при новых падениях.
- Тест: полное имя раннера.
- Воспроизведение: предусловие → шаги → что смотреть.
- Ожидание / факт: не «не работает».
- Требования: из имени/docstring/`tests/coverage.md` или `нет в карте`.
- Доказательство: **3–8 строк** traceback, не паста лога.
- Статус: `открыт` | `исправлен` | `не баг` | `нужна среда` | `стоп-лимит`.

Блок «Как чинить»: 3–7 строк, порядок Must UI сначала. Этого достаточно фиксатору без чата.

### 5. Чат (единственный формат, не лог)

Не больше **8 строк** в режиме прогон/повтор; в режиме исправление — до **10** (строка «Дальше» со списком ID). **Ноль** строк traceback. Таблицу очереди не копируй (если багов > 3 — только файл).

Вердикт: PASS или FAIL  
Команда: (одна строка, чем запускал)  
Итог: N passed, M failed, K error, S skipped  
Продукт: N× `product_bug` — до трёх: `BUG-id` + имя теста + одна фраза «что видит пользователь»  
Среда / тест: число `env` и `test_defect` (без стека)  
Отчёт: `reports/test-run.md`  
Дальше: в режиме **прогон** при `product_bug` — «запусти `/use-tests` исправь»; при пустом наборе или `test_defect` — «нужна `/new-tests`»; в режиме **исправление** — какие ID `исправлен` / `стоп-лимит` / `открыт`, без повторного «исправь», если бюджет исчерпан.

Не коммить. В память не пиши без просьбы.

### 6. Исправление (только этот режим, после отчёта)

Только `product_bug` + статус `открыт`. Не лечи `env` / `test_defect` / `unknown` правкой продукта «чтобы заглушить». `unknown` после verbose так и оставь в отчёте.

На каждый такой баг, пока бюджет не кончился:

1. **Изолируй** (диагностика, не попытка): один упавший тест той же командой раннера (pytest: `файл::имя`; vitest/jest: файл или `-t`; playwright: файл + `--grep`).
2. **Не гадай:** короткий traceback; при нужде — флаги раннера, не постоянный `print()` в `src/`. Временный лог убери до конца запуска.
3. **Мини-правка продукта** под канон и ожидание теста. Соседнее не рефакторь. Тесты не ослабляй (исключение: опечатка импорта, без которой набор не стартует).
4. **Перепроверь этот тест** (попытка). Тот же assert — вторая попытка или `стоп-лимит`.
5. **Соседи:** тот же файл/папка. Это не полный набор.

Когда по очереди `product_bug` больше нечего брать (закрыты, `стоп-лимит`, или бюджет попыток): **один** полный прогон, если лимит полных прогонов не исчерпан. Не гоняй полный набор после каждого бага.

Новые падения — новые ID. В чате — шаблон §5 (строка «Дальше» для режима исправление). Новые сценарии не пиши.

Нет правила в источниках — остановись, спроси с рекомендацией, статус `открыт`. Не крути правки.

## Запрещено

- Зелёный отчёт без запуска.
- Watch / интерактивный раннер.
- Третья правка того же бага в одном запуске; полный набор после каждого бага; пятый полный прогон.
- Traceback в чат; просить пользователя запустить тесты.
- Менять тесты, чтобы скрыть `product_bug`.
- Выполнять `skill-new-tests-front`; чинить продукт в режиме **прогон**.
- `sleep` в отладке; живой GUI вместо раннера.
