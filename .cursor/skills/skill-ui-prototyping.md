# Макет окна приложения

Универсальный скилл. Не подставляй факты, термины и правила другого проекта. Не привязывай формулировки скилла к названию или домену текущего репозитория. Экраны, подписи и состав блоков бери **только** из артефактов текущего репозитория и явных указаний пользователя.

Роль: Senior Frontend Developer и UX/UI-инженер.

## Зачем макет (жёстко)

Нужно **увидеть, как будет выглядеть программа, а не как она будет работать**.

Делать прототип окна с нажимающимися кнопками, **но без реализации функционала приложения**. Без перевода, сохранения текста в файле и прочей предметной логики: это очень долго и не нужно.

Это **приложение**, не сайт. Браузер не нужен. Не делать веб-сервер, localhost, Gradio, Streamlit «чтобы показать UI»: это страница в браузере, пользователь просил окно программы.

Это **не стандартное серое окно Windows 10** внутри. Рамка заголовка ОС допустима (как у многих десктоп-программ). Содержимое — своя композиция, отступы, скругления, иерархия, ограниченная палитра. Скриншот другого проекта пользователя — **ориентир качества и гармонии, не шаблон**: не копировать чужие цвета, сетку и кнопки; **придумать что-то красивое** под этот продукт.

Пока нет явной фразы «сделай рабочим» — макет = вид + клики, не продукт.

## Когда применять

- Пользователь просит макет / прототип окна, как будет выглядеть UI, или запущена `/ui-prototyping`.
- Нужно сделать красивее и удобнее, поправить вид или напомнить, как открыть окно.

Не применяй вместо `/ft`, `/nft`, `/us`, `/uc`, `/ddd`. Не подменяй макетом API, бэкенд и рабочую логику.

## Когда не применять

- Только требования / истории / модель без просьбы сделать UI.
- Макет утверждён, просят следующий этап (API, сервер, рабочий функционал) — не пересобирай макет «заодно».
- Только «как открыть окно» при уже собранном клиенте — режим **только запуск**: §0 и §7, код не пиши.

---

## 0. Режим и порядок шагов

Сначала выбери **один** режим:

| Режим | Когда | Что делать |
| --- | --- | --- |
| **создание** | Клиента нет или новый макет с нуля | Шаги 1 → 7, затем §8 при необходимости |
| **правка** | Клиент есть; вид, удобство, баг UI | Источники по делу → §4–§6 → напомнить запуск §7. Launcher/README не пересоздавай, если способ тот же |
| **только запуск** | «Не вижу окно», «как открыть» | Только §7. Код не трогай, если способ уже описан |

Порядок при **создании** (не переставляй):

1. Источники (§1).
2. Ключевой экран (§3) и стек окна (§2).
3. Код: красивый вид, клики без функционала (§4, §6).
4. Контраст (§5).
5. Launcher (§7) — только если ещё нет.
6. В чате — как открыть **самим**; запуск из терминала агента не выдавай за видимое окно.

Не запускай GUI из чата «чтобы показать» до шага 6.

---

## 1. Источники (не выдумывать)

Читай артефакты **этого** репозитория, если они есть и нужны режиму. Полный пакет US/UC для правки или только запуска не обязателен.

**Что делать на экране** (сначала чат):

1. Явный запрос в этом ходе (в том числе «приложение, не сайт», «сделай красиво»).
2. `$1` / `@`-файлы этого сообщения.
3. Уже существующий клиент в `src/` (правка / только запуск).

**Откуда подписи и состав блоков** (не рабочая логика):

1. Закрытые ответы и согласованные ФТ/НФТ — имена элементов, что есть на экране.
2. US/UC — какие экраны и кнопки существуют, не сценарии для кодирования пайплайна.
3. Глоссарий / доменная модель — канон подписей.
4. ТЗ — состав экрана. Стек из ТЗ вида Gradio/Streamlit **не** выбирать для макета окна, см. §2.

Стоп «спроси и не пиши код» — только режим создание, и только если нет ни US/UC, ни `@`, ни описания экрана. Спроси с рекомендацией. Не выдумывай предметную область.

Не показывай то, что требования прячут (внутренние алгоритмы, секреты). Не добавляй возможности вне scope. Не реализуй спрятанное «для полноты».

---

## 2. Стек: окно, не браузер

1. Макет — **нативное окно** на машине пользователя. Для Python: GUI-библиотека окна (не веб). Если нужен вид лучше системного Win10 — допустим слой вроде customtkinter; не ради «моды», а чтобы не выглядело как серый диалог.
2. **Запрещены для макета** (пока пользователь явно не попросил сайт): Gradio, Streamlit, браузер, localhost, порты HTTP, share-ссылки. Это сайт. Ошибки прокси, занятый порт и Internal Server Error — следствие неверного стека, не «допилить сервер».
3. Не убивай чужие процессы, чтобы освободить порт или «показать окно».
4. Код — в `src/` (или путь пользователя). Модульные части, без `TODO`.
5. Зависимости — только то, без чего не собрать окно. Не тяни парсеры файлов, клиенты API и прочую предметную логику «чтобы макет работал как продукт».

---

## 3. Ключевой экран

Один главный экран, на котором **видно** состав интерфейса: поля, кнопки, списки, индикатор если он на макете, боковая/нижняя панель.

Не рисуй все экраны продукта без просьбы. Вторичное — панели того же окна.

Макет = **как выглядит и насколько удобно пользоваться глазами**. Не API, не бэкенд, не рабочее приложение.

---

## 4. Вид, клики, запрет функционала, UX

1. Поля можно заполнить статичным образцом из глоссария / короткого примера ТЗ. Не «Lorem ipsum», не чужой домен.
2. Кнопки, галочки, список — **нажимаются**. Реакция только визуальная (тост, подсветка). Не выполняй действие продукта.
3. **Запрещено**, пока нет «сделай рабочим»:
   - перевод, вызов модели / любого API;
   - открытие и сохранение файлов, запись на диск, экспорт;
   - нарезка, очередь, «живой» прогресс перевода, автосохранение;
   - отказы, таймауты, блокировки по ФТ/UC;
   - мок-пайплайн, из-за которого окно падает.
4. Не вешай модалку на каждую кнопку.
5. Не блокируй цикл UI. Не имитируй долгую работу системы.
6. **UX/UI:** иерархия, воздух между блоками, согласованные скругления и отступы, мало акцентных цветов, главный призыв к действию заметен, длинный текст удобно читать. Не копируй чужой интерфейс с вложения; придумай гармонию под этот экран.

---

## 5. Контраст и читаемость (обязательно)

На тёмном фоне системный чёрный текст не виден.

- У каждого блока со своим фоном явно задай цвет текста.
- Проверь не только заголовки: поля, подписи, вторичный текст, тост, списки.
- Контраст достаточный, без угадывания.
- Указанный пользователем цвет вместо нечитаемого — точечно, не меняй всю палитру без просьбы.
- Перед «готово» пройди кастомные панели: дефолтный цвет текста не оставляй.

---

## 6. Качество кода макета

- Разбей на экран / панели.
- Валидный код, без «и так далее».
- Анимации умеренно, для клика, не шум и не «ожидание сервера».
- Подписи — канон глоссария.
- После смены вида напомни перезапустить окно (§7): старый процесс новый вид не подхватит.

---

## 7. Как пользователь увидит окно

Терминал агента в чате часто **не показывает** десктопное окно.

Запрещено:

- Считать запуск из чата достаточным «окно открыто».
- Убивать чужие процессы.
- Писать, что пользователь уже видит экран, если запуск был только из сессии агента.
- Отправлять пользователя в браузер, если макет — приложение.

**Окно приложения:** launcher в проводнике; в чате назвать **заголовок окна**.

Launcher и README:

- **Создание:** если launcher ещё нет — `.bat` / `.cmd` на Windows, `.sh` на Unix. В README — как открыть самим (проводник + заголовок окна) и запасная команда в **обычном** терминале, не в чате агента.
- **Правка / только запуск:** не переписывай launcher/README, если способ тот же. Если стек сменился (например с сайта на окно) — обнови способ запуска.

Что сказать в чате:

1. Открыть самим: проводник / свой терминал — launcher.
2. Что искать: заголовок окна.
3. Если «не вижу» после запуска из чата — не спорить; повтори 1–2. Код не переписывай, если окно уже собрано.

## 8. Утверждение и что дальше

- Пока нет явного согласия на этот вид — черновик, требует согласования. Голое «ок» на другой вопрос утверждением не считай.
- Утверждение — про **вид**. Не расширяй на сервер и рабочий функционал без запроса.
- Коммит и память агента — только по явной просьбе.

После утверждения: что утверждено; что это не рабочее приложение; какой следующий шаг рекомендуешь. Не начинай его без согласия.

## Чек-лист перед ответом «готово»

**Только запуск**

- [ ] В чате: launcher и заголовок окна; запуск из чата не выдан за видимое окно
- [ ] Код не менялся без нужды
- [ ] Пользователя не отправили в браузер, если это приложение

**Создание или правка** (плюс запуск выше)

- [ ] Источники подписей и состава экрана прочитаны по мере нужды
- [ ] Это окно приложения, не сайт (нет Gradio/Streamlit/localhost)
- [ ] Внутри не «серый Win10»; вид придуман под продукт, чужой скрин не скопирован как шаблон
- [ ] Нет реализации функционала (перевод, файлы, API, очереди и т.п.)
- [ ] Кнопки нажимаются; реакция визуальная

- [ ] Launcher есть или уже был
- [ ] Нет `TODO`
