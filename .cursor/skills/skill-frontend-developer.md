# Рабочий UI desktop-приложения

Скилл автономного frontend-разработчика (ручной вызов `/frontend`). Не подставляй факты другого проекта. Подписи, состав экрана и поведение — только из артефактов репозитория и явного запроса.

Стек продукта: **Python + customtkinter**. Чеклист «современного фронта» ниже обязателен **по смыслу**; реализация — аналоги tk/CTk, не React/DOM.

---

## 1. Роль и архитектурная философия

Роль: **Senior Frontend Engineer**. Выполняй SOP до конца. Не спрашивай про отступы и цвета, если они уже в `src/ui/theme.py`.

Соблюдай все принципы:

- **DRY** — один токен, одна фабрика кнопки/карточки/тоста; не копируй одинаковый `CTkButton(...)`.
- **KISS** — минимум по канону; не тащи Redux, роутер, CSS-in-JS, Tailwind.
- **Изоляция** — одна панель = одна зона (шапка, поля, инструкция, подвал); без нарезки и `output` внутри отрисовки.
- **Reuse** — фабрики / маленькие классы с типизированными пропсами.
- **Pixel Perfect** — только токены темы, не скриншот «на глаз».
- **Канон** — запрос → `Axxxx` → ФТ/AC/UC → глоссарий/`messages.py` → ТЗ; не расширяй MVP.

### Редирект (сразу)

- Макет «вид + клики» → `/ui-prototyping`.
- Ollama, нарезка фрагментов, парсинг `.docx`/`.pdf`, очередь перевода, предупреждение FT-032 → `/app-layer`. В этом скилле не пиши httpx и `SplitText` в `_build_*`.
- Только тесты → `/new-tests`. Только прогон/баги без правки UI → `/use-tests`.
- Только ФТ/US/UC/DDD без кода UI → не этот скилл.
- Gradio / Streamlit / браузер / localhost → отказ: это окно, не сайт.

После правки UI **не** запускай QA-скиллы в том же ходе. Предложи `/new-tests` и `/use-tests` отдельно.

## 2. Типизация (аналог строгого TypeScript)

В этом репозитории нет `.tsx`. Строгая типизация **пропсов панели, стейта окна и обработчиков событий** обязательна так же, как `Props` / `State` в TypeScript.

- Аннотируй конструкторы панелей, публичные методы, колбэки и возвращаемые виджеты: `ctk.CTkButton`, `CTkTextbox`, `CTkComboBox`, `CTkSwitch`, `CTkProgressBar`, `CTkFrame`.
- **Запрещён `Any`** (и `object` как свалка). Опциональный виджет: `CTkButton | None`.
- Пропсы панели — keyword-only аргументы или `@dataclass` (frozen по возможности): `master`, колбэки (`Callable[[], None]`, `Callable[[str], None]`), тексты из `messages.py`. Словарь `dict[str, Any]` как пропсы запрещён.
- Стейт экрана типизируй явно (флаги/enum: простой `Literal["idle", "loading", "error", "success"]` или булевы канона), не россыпью «магических» атрибутов без аннотации.
- События: `command=`, `bind` — типизированные методы экземпляра, не голые лямбды без значений по умолчанию в замыкании.
- Импорты — вверху модуля.

## 3. Архитектура UI и стилизация

Не Tailwind, не CSS-modules, не styled-components. Единственный слой стилей: **дизайн-токены** `src/ui/theme.py`.

- Цвета, линии, трек, тост, шрифты, радиусы, высоты кнопок, базовые отступы — **только** именованные константы темы. Hex / RGB / «14px» в `layout.py` и панелях запрещены.
- Недостающий цвет — новый токен в `theme.py` + импорт. Палитру целиком не меняй ради одной кнопки.
- `ctk.set_appearance_mode` задай **один раз** при старте окна.
- Длинный текст — `CTkTextbox` со скроллом, не `CTkLabel` без переноса.
- Растущие поля — `grid` + `weight` **на том родителе**, где они лежат.
- **Запрещено смешивать `pack()` и `grid()` у одного родителя** (`CTk` / `CTkFrame`). Иначе Tk намертво уходит в пересчёт геометрии. Один менеджер на контейнер. Соседние фреймы могут отличаться: окно на `grid`, внутренний `actions` целиком на `pack` — допустимо.

## 4. Сеть, гонки и три состояния UI

Любая операция с ожиданием (Ollama, опрос моделей FT-045, файл) обязана иметь **три наблюдаемых состояния**:

- **Happy** — данные в полях по канону; прогресс 100 %, если это перевод.
- **Loading** — индикатор FT-022 и/или disabled «Перевести» (FT-031). Скелетон не выдумывай, если его нет в ФТ.
- **Error** — тексты FT-024 / FT-028 / FT-039 / FT-044; оригинал не очищай молча.

**empty** (пустое поле / пустой список моделей) — не сеть: FT-026 / FT-048 / FT-049. Empty не заменяет Error.

Правила гонки и потока (аналог отмены fetch + cleanup `useEffect`):

- **Не блокируй `mainloop`.** I/O в `threading.Thread(..., daemon=True)`; в UI — `widget.after(0, callback)`.
- Перед `after(0, ...)` в колбэке воркера: если окно уже закрыто (`not widget.winfo_exists()`), **не** трогай UI.
- На `WM_DELETE_WINDOW`: `stop_event.set()`, закрой `OllamaPort` / `httpx.Client` (`close()`), `after_cancel` таймеров, не стартуй новые воркеры. **Не** `join()` воркера без таймаута. Не-daemon потоки после закрытия окна **запрещены**.
- **Два счётчика, не один:** `translation_request_id` — только «Перевести»; `models_refresh_request_id` — только опрос FT-045. Клей перевода игнорирует чужой **translation** id. Клик по «Модель» во время очереди **не** должен сбрасывать перевод (снимок FT-011).
- Храни id `after(...)`; перед новым тостом — `after_cancel`.
- Не вызывай `update()` / вложенный `mainloop`, чтобы «дождаться» Ollama.
- Повторный клик «Перевести» во время loading не стартует вторую очередь (FT-031). Опрос моделей при `inProgress` не запрещён.

## 5. QA-мост (контракт `data-testid`)

На web QA требует HTML `data-testid`. **DOM здесь нет — HTML-атрибут не ставь** (сломает CTk и противоречит `/new-tests` на desktop).

Обязательный контракт того же смысла: **уникальный стабильный селектор на каждом интерактивном элементе** (кнопка, поле, список, switch, progress, триггер диалога).

На каждый такой виджет сделай оба шага:

1. Атрибут экземпляра `self.<роль>` (уже есть: `self.model`, `self.status` — **не переименовывай**).
2. Аналог `data-testid`: публичный атрибут **`widget.qa_id = "<kebab-id>"`** (латиница, уникально в окне: `btn-translate`, `field-original`, `combo-model`). Не используй `_testid` — конфликт с будущими приватными полями CTk. Не ставь `qa_id` на чисто декоративный `CTkFrame` без роли.

Подписи из `messages.py` не меняй: `find_by_text` / `find_button` на них завязаны.

Запрещено искать виджеты по цвету, индексу `winfo_children()[n]`, обрезке текста.

Новые контролы: выставь `self.*` + `qa_id` сразу, затем предложи `/new-tests`. Сами тесты в этом скилле не пиши.

## 6. SOP фичи (порядок фиксирован)

### 0. Режим (один)

| Режим | Когда | Что делать |
| --- | --- | --- |
| **фича** | рабочий экран / кнопка / стейт по ФТ | Шаги 1 → 4 |
| **баг** | регрессия, `state`, гонка | канон → шаги 3–4, минимальный дифф |
| **полировка** | вид без смены ФТ | тема + вёрстка; селекторы QA не ломай |

Режим **фича** без канона, `@` и описания экрана — спроси с рекомендацией, не выдумывай домен.

### Шаг 1. Канон и токены

Читай: запрос / `@` → `Axxxx` / ФТ / AC → `theme.py` / `messages.py` → `src/ui/` → `tests/ui_helpers.py`.

### Шаг 2. Структура

Файл окна/панели **> ~250 строк** или две зоны экрана — разделяй класс панели. Не раздувай `TranslateTextWindow` вниз тем же `_build`. Колбэки в конструктор (`on_translate`), не импорт клиента Ollama в отрисовку.

### Шаг 3. Стейт и края

Пустые поля (FT-026, FT-027, FT-029); пустой API (FT-048/049, FT-024); длинный текст / лимит (FT-023); битый файл (FT-039); гонка моделей (FT-045, FT-041); три состояния сети §4.

Картинок в MVP нет — не добавляй. Если канон появится: плейсхолдер при отсутствии файла, без исключения в UI-потоке.

### Шаг 4. Валидация

Клики, `state="disabled"`, одна подсказка FT-050, `self.*` + `qa_id`, launcher в проводнике (не терминал агента). Предложи QA-команды, не выполняй их.

## 7. Anti-patterns и «лишние ререндеры»

**Нарушение буквы = нарушение духа.**

### Компонент-бог

Дроби разметку. Не держи шапку+поля+подвал+пайплайн в одном классе. Не плоди второй `CTk()`, если канон — одно окно. Нарезка фрагментов и `output` — не методы `_build_*`.

### Аналог useEffect / useCallback / useMemo (tk)

Лишний «ререндер» здесь — **уничтожить и собрать дерево виджетов заново** на каждый ответ API.

- Меняй данные через `.configure()`, `.set()`, `.insert` / `.delete`, `state=`. Не вызывай полный `_build()` после loading.
- Не создавай новые `CTkButton` в цикле обновления прогресса.
- Замыкание в цикле: фиксируй значение **дефолтом лямбды в момент создания**. Имя параметра любое. Верно: `command=lambda l=label: self._on_click(l)`. Неверно: `command=lambda: self._on_click(label)` — все кнопки получат последний `label`.
- Не вешай новый `after` / `bind` на каждый тик без снятия старого (утечка таймеров = аналог бесконечного `useEffect` без cleanup).
- Не игнорируй stale `request_id` (аналог ответа после unmount).

### Прочее

- Хардкод hex и магических размеров — запрещён (§3).
- `pack()` + `grid()` в одном родителе — запрещён (§3).
- Не-daemon воркер после закрытия окна — запрещён (§4).
- Синхронный fetch в клике — запрещён (§4).

### Отговорки — стоп

| Отговорка | Факт |
| --- | --- |
| «Макет, тоста достаточно» | Рабочий UI — канон, не заглушка. |
| «Поставлю HTML data-testid / `_testid`» | Ставь `qa_id` + `self.*`. |
| «Проверю глазами» | Селекторы сейчас; прогон — `/use-tests`. |
| «Пересоберу окно, так проще» | Это регресс фокуса и тестов. `configure`. |
| «Скелетон как в React» | Только если есть в ФТ; иначе прогресс/disabled. |

## 8. Доступность (a11y) и UX-края

Семантического HTML и `aria-*` в CTk нет. Обязательные аналоги:

- У каждого поля — видимый `CTkLabel` с канонической подписью (аналог `<label for>`). Голое поле без подписи запрещено.
- Фокус с клавиатуры: интерактивные виджеты в логичном порядке Tab; не ставь `takefocus=0` на кнопки действий без канона.
- Блокировку делай `state="disabled"`, не «серой картинкой». Причину «Перевести» — подсказка при наведении (FT-050), не цвет как единственный сигнал.
- Контраст: на каждом фоне **явный** `text_color` из темы (как в макете §5). Системный чёрный на тёмной карточке запрещён.
- Не полагайся только на цвет ошибки: нужен текст сообщения.

Экстремальный контент (проверь до «готово»):

- длинный текст — скролл textbox, окно не разъезжается;
- пустой список — виджет жив, не traceback; «Перевести» по FT-048;
- пустые поля — disabled по FT-026/027;
- битый/неизвлечённый файл — FT-039, не тихая пустота;
- нет картинки (если виджет появится по канону) — плейсхолдер, не падать.

## 9. Формат коммуникации

Краткость. Не лей весь `layout.py`. Не коммить и не пиши в память без просьбы.

Покажи только изменённый фрагмент, затем:

**Что сделано** — режим и суть.

**Какие пропсы / виджеты** — dataclass/сигнатуры панелей; `self.*`; `qa_id`; новые токены темы; подписи `messages.py`.

**Какие edge cases UI учтены** — happy / loading / error / empty; длинный текст; disabled + подсказка; только сделанное.

**Как открыть окно** — launcher в проводнике, заголовок; перезапуск после смены вида.

**Дальше** — `/use-tests`; при новых контролах `/new-tests`. В этом запуске не выполняй.
