# Создать или обновить автотесты фронтенда

Прочитай и выполни `.cursor/skills/skill-new-tests-front.md` целиком. Команда `/new-tests` запускает этот скилл.

Не выполняй `.cursor/skills/skill-use-tests-front.md` в этом запуске — даже если в запросе есть «и прогони». Прогон — отдельная команда `/use-tests`.

## Ввод

`$1` и дальнейший текст — уточнение: какие экраны / ID требований (FT, US, UC, NFT, Axxxx) покрыть; только инвентаризация; обновить устаревшие тесты после смены требований.

Если текста нет — изучи требования и существующие тесты проекта, добавь тесты на пробелы MVP. Не расширяй scope «для полноты». Набор не гоняй.

## Какой режим

Смотри на ввод, отдельную подкоманду выбирать не нужно.

- **дополнение** — «напиши тесты», `/new-tests`, указаны фичи. Добавляй только непокрытое.
- **инвентаризация** — «какие тесты есть», «чего не хватает», без просьбы писать код. Файлы тестов не создавай.
- **обновление устаревших** — канон требований сменился, старые ожидания в тестах неверны. Правь только эти ожидания.

Продуктовый код: логику не меняй. На web допустимо только добавить `data-testid` (без смены поведения), если без него селектор хрупкий. Папку `test-data/` не используй без прямого задания разработчика.

Если запрос — только прогон / «какие баги» / «исправь падения» без написания тестов — **остановись**. Напиши, что нужна команда `/use-tests`. Файл `skill-use-tests-front.md` в этом запуске не выполняй.

## После выполнения

Кратко: пути файлов, сколько тестов добавлено или обновлено, чек-лист слоёв (happy/edge/negative), какие ID требований закрыты, какие пробелы оставлены.
Предложи `/use-tests` отдельной командой, в этом запуске её не выполняй.
Не коммить и не пиши в память агента без явной просьбы.
